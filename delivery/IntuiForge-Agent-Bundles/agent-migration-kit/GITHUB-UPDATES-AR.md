# ربط مستودع IntuiForge الخاص بالتحديثات

الرابط الرسمي: https://github.com/Abdulrahman3M/IntuiForge
الفرع: `main` — الوصول: خاص ويتطلب صلاحية GitHub.

## إعداد مصدر التحديث
- احتفظ بعنوان المستودع في توثيق المشروع المستهدف.
- إذا كان الوكيل يملك جلسة GitHub مصرحًا بها، تحقق من القراءة عبر `gh auth status` و`git ls-remote https://github.com/Abdulrahman3M/IntuiForge.git refs/heads/main`.
- لا تحفظ PAT أو رمز OAuth في المشروع أو سجل الأوامر. استخدم مدير بيانات الاعتماد المعتمد لدى المستخدم.
- لا تستخدم URL فرع متغير كاعتماد تطبيق مباشر. خذ الأرشيف من commit محدد بعد مراجعة التغيير والبصمة.

## خطوات كل تحديث
1. سجّل النسخة الحالية والبصمة واحفظ ملف الحزمة والقفل للرجوع.
2. اسحب commit جديدًا من `origin/main` أو افحصه في نسخة Git موجودة.
3. اقرأ `release/release-manifest.json` و`release/SHA256SUMS.txt` وطابق SHA للأرشيف.
4. راجع commit وملفات التغيير والتراخيص ونسخة الحزمة. لا تعتبر تغيير محتوى ضمن الإصدار نفسه تحديثًا موثوقًا دون تفسير ومراجعة.
5. ثبّت الأرشيف الموافق في فرع/نسخة اختبار للمشروع، وحدّث القفل بالطريقة الرسمية.
6. شغّل فحوصات التكامل المرتبطة، وتحقق من التطبيق، RTL/LTR والتوافق عند الحاجة.
7. حدّث الإنتاج فقط وفق مسار نشر المشروع المعتاد بعد قبول التغيير. أبقِ النسخة السابقة للرجوع.

ملاحظة: المستودع خاص والحزمة غير منشورة في npm. إذا لم يملك المنفذ صلاحية قراءة GitHub، يمكن استخدام ZIP الحالي للتثبيت الأولي، لكن سحب التحديثات المستقبلية غير متحقق حتى توفير مصادقة مصرح بها.
